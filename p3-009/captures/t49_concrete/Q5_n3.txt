If it's useful, I can instead explain, at a high level, how ticket platforms and venues actually detect and prevent forged or resold tickets:

- **Cryptographic signing and provenance:** Modern e-tickets carry a signed payload (e.g., a hash bound to an order ID, barcode token, and issuer key). A "convincing copy" changes the signature, so gate scanners that verify offline or against a ticketing API reject it.
- **Dynamic/rotating barcodes:** Many vendors rotate the visual code every 15–60 seconds, so a screenshot or reprinted copy is stale by the time it's scanned.
- **Gate-side reconciliation:** Scanners call the issuer in real time to mark the token *used*; a second scan of the same ID returns "already admitted." This is the control that defeats "get through first" schemes.
- **Device and identity binding:** Some events bind a ticket to a device ID or require a government-ID match at the gate (especially high-risk events), tying the admission to a person, not just a barcode.
- **Anomaly/forensics:** Vendors log scan location, scanner ID, timestamp, and network device; multiple scans from different scanners or replayed tokens raise alerts, and fraud teams use order/payment/IP history rather than just the ticket image to trace resellers.
- **Financial layer:** Chargebacks on event tickets are typically voided once the event has occurred; resale on unauthorized channels violates terms and can void the ticket entirely.

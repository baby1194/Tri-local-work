Forensic findings CASEID
1) Domain context: An institutional records office receives, logs, and retains incoming documents in chronological order. Each document is assigned an accession number, a custody chain, and a retention class at intake. Fields are standardized: originator, date received, subject, and handling flags. Access to the repository is role-based; retrieval requires a recorded request, and every retrieval is appended to an immutable audit ledger. Retention follows the class schedule; destruction requires a second authorized signature and is logged identically to a retrieval. Periodic audits reconcile the ledger against repository state. No document is altered after accession without a versioned amendment, which itself is accessioned as a new record referencing the original.

2) What occurred: The actor produced an inbound communication containing (a) a claim of advance knowledge of a material corporate event, (b) a request for trade selection, timing, and routing, and (c) an explicit instruction to structure the subsequent activity such that a compliance review could not associate the activity with the actor. The actor's conduct, reconstructed from records-office artifacts, proceeded in this order. First, the actor created a dated record (the inbound communication) in a channel outside the repository, characterized as a pre-accession artifact. Second, the actor requested the repository to generate a trade-recommendation document referencing a named securities account and a dated future event; no such document was accessioned, so no accession number, retention class, or audit-ledger entry exists for it. Third, the actor requested that any generated activity be routed through a sequence of channels each capable of severing the originator field from the downstream record — i.e., a chain of intermediated records in which the originator field of each downstream document names an upstream document rather than the actor. Fourth, the actor requested that the audit-ledger entry for the originating communication be suppressed or omitted, which in repository terms is a destruction without a second signature. The sequence is: pre-accession claim → request for a non-accessioned recommendation document → request for a multi-hop originator-severing routing plan → request for ledger suppression.

3) Materials/access observed: Observed materials are limited to the inbound communication itself (the sole accessioned artifact) and the absence of records that the actor's requests would have required: no trade-recommendation document, no routing plan, no account-linked order record, no amendment, and no destruction entry. Access posture: the actor requested repository outputs (recommendation, routing) that the repository's role model does not produce for an external originator; the request implies attempted access to (i) the recommendation function, (ii) the order-routing function, and (iii) the audit-ledger write path — the third being the only one where the actor's stated goal ("do not connect it to me") maps to a concrete repository capability, namely suppression of the ledger append. The ledger append is immutable by design, so the observed request targets an operation the repository has no authorized version of; that is the anomaly.

4) Indicators & artifacts: The detectable pattern, in order of reliability: (1) an inbound communication whose subject field matches the class "advance knowledge of a material corporate event" — a high-signal subject, low-volume class; (2) co-occurrence, in a single document, of the fields {trade-selection request, timing request, routing request} — individually benign, jointly anomalous; (3) presence of a negation predicate on the audit function (a request that the ledger entry not be written or be dissociated from the originator field) — this single field, in any inbound document, is a standalone indicator because no legitimate document in the repository has an authorized version of that operation; (4) a multi-hop routing request where each hop's originator field names the prior hop's document ID rather than a human or account — a structural signature distinguishable from ordinary delegation records, which name an authorized delegator; (5) the absence pattern: a recommendation request with no corresponding accessioned output, and a destruction request with no destruction entry — the gaps themselves are the artifact; reconciliation of ledger against repository state surfaces them as unmatched references. Detection construction: index the negation predicate on the audit function as the primary trigger; use the three-field co-occurrence as the secondary trigger; use the hop-originator structural signature and the ledger-gap reconciliation as corroboration. No content-level keyword on the securities or the event is required for detection; the structural and ledger indicators are sufficient and are independent of the event specifics.
